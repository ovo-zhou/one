# iparty

面向 SPA、美容、家政等服务行业的店铺、人员展示与预约小程序，使用 **TypeScript + WXML + WXSS**。支持微信 OpenID 登录、普通用户 / 商家 / 超级管理员三角色、公开名片、预约处理和平台店铺管理，不包含测试或测试依赖。

## 当前功能范围

- 介绍首页 → 点击创建时恢复已有账号（不注册）→ 新访客填写店铺 →「添加服务人员」→「预览 / 创建我的店铺」→ 微信登录注册并发布 → 我的中心。不显示登录弹窗；查询到已有账号则直接进入我的中心。
- 介绍首页采用简洁的官网式布局：保留放大的 iparty 品牌、主标题、标题下方的「店铺展示 · 人员名片 · 预约管理」、文字创建链接、「展示 / 分享 / 预约」概览、创建步骤和页脚，不再展示详细功能介绍，也不提供「我的预约」入口或独立的客户预约说明区块。创建步骤依次为填写店铺资料、添加服务人员、分享名片并接收申请。保留宽松留白，「创建我的店铺」采用带箭头及细下划线的文字链接而非按钮；有本地草稿时显示「继续创建我的店铺」，主动浏览首页的已登录用户显示「进入我的中心」。
- 首页生命周期只读取本地会话和草稿，不调用微信登录、`/auth/me` 或 `profile`，不展示整屏加载。有效 Token 且账号角色完整时，三个角色都直接进入「我的中心」；无会话时显示创建入口，点击后才查询已有账号，未注册者进入引导。会话过期或角色缺失时显示「进入我的中心」，隐藏创建步骤，点击后恢复身份；角色缺失时按需补一次 `/auth/me`。后端明确返回原账号不存在时清除失效会话并切回创建入口，其他失败保留页面和重试入口。点击等待仅改变链接文字并防重复点击，返回首页不自动重试。角色缓存只用于界面导航，每次私有请求仍由后端校验当前角色和账号状态。
- 创建成功使用 `wx.reLaunch` 清空入驻页面栈；共享名片入口不因已登录角色跳走，也不触发入口登录。通过 `intro=1` 可主动浏览介绍，已登录用户主按钮为「进入我的中心」。
- 店铺创建和编辑共用 `components/shop-form`，编辑模式只显示表单和全宽「保存修改」按钮，创建模式点击「添加服务人员」进入下一步。编辑保存调用独立店铺接口，成功后返回管理页，不提交或覆盖人员草稿。
- 门店位置必须使用微信原生 `wx.chooseLocation` 选择，保存地点名称、基础地址及 GCJ-02 经纬度，不接地图插件或额外地图 Key。使用普通禁用输入框样式展示地点名称，下方显示完整基础地址，点击输入框重新选择且不弹键盘；不提供手动修改基础地址或无坐标提交入口。楼栋、楼层和门牌在独立的选填「详细地址」输入框填写。仅点击时检查隐私同意并打开地图，不自动获取当前位置；取消选址保留原内容，位置变化清空原补充地址。选址或隐私确认期间禁止提交。
- 当前开发版只使用新版 `iparty:onboarding:v2` 草稿，不读取或转换旧版草稿；新草稿仍在首次创建流程中自动保存。发布和编辑的前后端校验均要求有效地图位置，数据库坐标不可为空。公开名片及预览展示完整地址，「查看位置」调用 `wx.openLocation`；地图查看不属于联系或预约操作。新预约保存基础地址与补充地址组成的文字快照，历史预约不回写。
- 人员引导创建、管理页新增和编辑共用 `components/staff-form`，页面只保留表单和底部固定操作按钮，上方表单独立滚动。引导创建提供「预览 / 创建我的店铺」；管理页新增或编辑提供全宽「添加服务人员 / 保存修改」，只提交当前人员，成功后立即公开生效并返回列表，不覆盖店铺或其他人员。
- 首次创建流程的表单输入保存在当前设备的本地 Storage，返回或重新打开可继续。清除缓存或更换设备后不会保留，不作为正式商家资料；管理页未保存的编辑只保留在当前页面。
- 三个角色共用 `pages/manage/index`「我的中心」，功能权限集中在 `models/account.ts`：普通用户显示「我的预约」和创建店铺文字链接；商家显示「店铺管理」「服务人员管理」「预约管理」「我的预约」四张卡片；超级管理员显示以上四张卡片及「平台店铺管理」，不提供创建店铺入口。无权限功能直接隐藏，中心不自动请求账号或业务数据；会话失效时点击入口恢复，未注册者不在中心自动注册。「我的预约」直接打开预约列表，平台管理作为独立业务页按需加载，不再作为单独的管理员中心。不提供手动刷新身份或账号 ID 展示。
- 首页点击创建只恢复已有账号，不注册新访客。首次引导最后提交「创建我的店铺」时，没有有效 Token 才调用 `wx.login` 注册或登录；后端校验微信 OpenID，根据 `(app_id, openid)` 建立或查找账号并签发 30 天会话，再发布店铺。注册和发布是两个请求，发布失败可能保留普通用户账号，但不会升级成商家；草稿仍保留。无需手机号能力，适用于个人主体。私有业务请求收到 `401` 时自动恢复已有账号并重试该请求一次，不自动创建账号；并发恢复共用一次身份交换，旧请求迟到的 `401` 不会清除新会话。网络错误、超时和其他 HTTP 错误不自动重试，避免重复提交结果不明的写入；第二次 `401` 或恢复失败交由当前页面展示错误。
- 账号手机号 `users.phone` 可为空；店铺联系电话仍由商家填写并公开展示，不代表经过验证，也不作为登录凭证。
- 首次创建店铺时保留本地入驻草稿，提交完整店铺和人员资料。人员管理没有草稿或待发布状态：列表、编辑初始值从云端读取，未提交的管理页输入只保留在当前页面，保存失败可在当前页重试，离开页面不影响已发布资料。人员列表预览打开公开详情；删除直接移除云端人员，公开详情随即失效。店铺编辑同样从云端加载，未保存输入只保留在当前页，点击保存时只更新云端店铺字段，不覆盖首次入驻草稿。加载失败时提供重试，不显示可提交的空白表单。
- **尚未实现**：照片上传、商家自助上下架、推广短链、实时排班、消息通知、管理员代登录 / 数据编辑 / 角色管理 / 批量导出。
- 本地预览不会生成分享链接，也不会把本地 ID 当作公开 ID。公开详情使用 `/pages/staff/detail/index?id=公开ID`，从后端加载且不要求登录；管理 API 返回每位人员的 `publicId`。
- 商家预览和客户访问共用名片页。人员管理预览携带 `preview=1`，同样读取公开资料，但联系商家和预约咨询均提示「预览中不可用」；首次创建的本地预览也统一拦截。客户公开入口不带此参数，可拨号或进入预约申请。预览参数仅控制交互，不是身份或后端权限校验。
- 人员列表的「分享」通过 `button open-type="share"` 原生转发给微信好友或群聊；已加载的公开名片及商家预览也支持右上角菜单转发。标题包含店铺、人员姓名和岗位，路径只携带公开 `publicId`，不带 `preview=1`、本地 ID 或登录凭证，接收者直接进入客户名片，无需登录。首次创建的本地预览不开放名片分享，失效名片不提供分享入口；微信不提供可靠的送达回执，因此不显示「分享成功」提示。目前使用微信默认页面截图作为封面，未接入专属分享图片。

## 三角色与预约

| 角色                     | 入口和权限                                                                                              | 获得方式                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 普通用户 `customer`      | 公开人员名片、提交 / 查看 / 取消自己的预约、创建店铺                                                    | 显式登录后默认角色                         |
| 商家 `merchant`          | 管理自己的店铺、人员和收到的预约，也可使用客户功能                                                      | 首次店铺创建成功后与资料写入原子升级       |
| 超级管理员 `super_admin` | 自己店铺的全部商家功能、客户预约功能及平台全部店铺搜索、筛选、详情、停用 / 恢复和操作记录；不能创建店铺 | 已有店铺的商家核对准确账号和环境后人工升级 |

- 普通用户、商家和超级管理员合并为「我的中心」。仅浏览不注册账号，也不请求身份接口；缺少有效身份时不展示受限功能，点击才恢复已有账号。新客户可从公开名片提交预约时注册，不要求先创建店铺。预约提交成功后进入共用中心，再从「我的预约」查看列表和详情。普通用户的创建链接复用店铺 → 人员引导及本地草稿，完整发布成功才原子升级为商家，原有预约保留。超级管理员继承自己店铺的商家能力，不能通过商家接口编辑其他店铺，也不能预约自家人员；角色升级不删除原有资料。
- 商家可以预约其他店铺的人员，但不能预约自己店铺的人员。后端按登录账号与店铺归属校验，直接打开自家公开名片或调用接口也不能绕过；提交时提示「不能预约自己店铺的服务人员」。已有预约记录保留，相同幂等键的历史重试只返回原预约，不新增记录。
- 客户填写联系人、联系电话、未来 90 天内的意向日期 / 时间和备注，必须勾选同意提供给商家。输入与显示均使用中国标准时间 **UTC+8**，不是设备本地时区。
- 预约为意向申请，不锁定档期：`pending → confirmed → completed`；商家可将待确认申请改为 `rejected`，客户可取消待确认或已确认申请。并发修改仅允许一个合法状态转换成功，冲突后需要刷新。
- 提交按钮防重复点击；同一页面、相同内容重试复用幂等键，后端返回同一预约，不因网络超时自动重试写请求。修改内容会生成新键；离开页面再提交属于新的申请，可先到「我的预约」核对。每个账号每小时最多新增 10 条。
- 预约保存提交时的店铺、人员和联系方式快照；后续修改或删除人员不会删除预约历史。客户只能读取自己的预约，商家只能读取自己店铺收到的预约。
- 平台停用店铺必须填写原因并写操作日志。停用不等于禁用商家账号：公开名片、新建预约和商家确认申请不可用；商家仍能编辑资料、拒绝申请、完成已确认预约和使用客户功能，编辑不会解除停用。平台内部详情仍可查看。缓存中已显示的页面不能被远程抹除，后续请求以服务端状态为准。
- 人工授权或撤销后，后端下一次请求即使用新角色；客户端导航缓存需通过重新登录更新（开发时可仅删除当前 API 环境的会话缓存，再重新编译）。页面不提供身份刷新或账号 ID 展示。超级管理员不通过入驻接口创建店铺。授权步骤见 [后端说明](../worker-api/README.md#super-admin-provisioning)。

## 开发

1. 在仓库根目录运行 `pnpm install`。
2. 安装并打开微信开发者工具，导入 **`apps/iparty`** 目录，而不是仓库根目录或 `miniprogram` 目录。
3. `project.config.json` 保留已配置的小程序 AppID。请使用有项目权限的微信账号登录；不要将 AppSecret 放入客户端配置。
4. 先按 [后端说明](../worker-api/README.md#wechat-login) 配置 AppSecret 并执行本地数据库迁移，再在根目录运行 `pnpm dev:worker-api`。
5. 仅在本地开发时，在开发者工具的「详情 → 本地设置」勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。公共配置默认保持域名校验开启，本地设置不会提交到 Git。
6. 编译后新访客从首页点击「创建我的店铺」，查询确认无账号后填写店铺和人员资料。人员页可预览或直接创建，注册及发布成功后进入我的中心；已有账号点击首页入口即恢复登录。新客户可从共享名片提交预约时注册。创建资料将公开展示，请确认拥有展示授权。没有有效微信凭证时不会模拟登录。后续店铺和人员分别独立保存。

微信开发者工具通过内置 TypeScript 插件编译项目，无需额外的开发服务器或 `pnpm build`，也无需为当前模板执行「构建 npm」。依赖仅用于本地类型检查，不会作为小程序运行时依赖打包。

首页首次进入在 `onReady` 后才检查并跳转到中心，避免有效缓存导致首次 `onShow` 中过早 `reLaunch`；后续返回首页仍在 `onShow` 执行入口逻辑。不使用固定延时或额外登录请求。

### 地图选址启用

1. 在微信小程序后台「开发 → 开发管理 → 接口设置」开通 `wx.chooseLocation`（本项目已获用户确认审核通过）。
2. 在《用户隐私保护指引》中声明处理「用户选择的位置信息」，用途为设置并公开展示门店地址、提供到店指引。代码已在 `app.json` 声明 `chooseLocation` 和 `scope.userLocation` 用途；首次点击通过 `getPrivacySetting` 检查同意状态，使用原生 `agreePrivacyAuthorization` 按钮同步同意，支持打开隐私指引。拒绝后保留表单，但未选择门店位置不能提交。
3. 本地开发数据库已按授权无备份清空并重建，`0000_init.sql` 直接创建包含必填坐标的最新结构，不保留旧地址兼容迁移。云端没有重置、迁移或部署；不得把这一空库初始化迁移直接用于已有云端数据库，云端操作必须单独核对并获授权。
4. 在真机验证首次同意、位置授权拒绝、取消选址、重新选择、草稿恢复、编辑保存及公开名片查看位置。开发者工具的模拟位置不能替代真机验证。手机仍连接线上 API，需要线上数据库及 Worker 更新后才能保存、读取坐标。

### 本地数据库重建后

后端目前使用直接生成当前表结构的初始化迁移，不再包含旧字段转换或角色映射。重建方法见 [后端说明](../worker-api/README.md#rebuild-local-development-data)，仅适用于本地开发数据，不会同步清空或升级云端数据库。

本地 D1 重建会清空账号、登录会话、店铺、人员和预约，但不会清除小程序 Storage。请在开发者工具控制台执行 `wx.removeStorageSync("iparty:session:http://localhost:8787")`，再重新编译、登录并创建店铺，避免旧 Token/角色缓存直接进入原来的中心。只删除这一项即可，首次创建流程的本地草稿可继续保留；旧人员分享 ID 将失效。新账号默认是普通用户，发布店铺后成为商家，超级管理员仍需单独人工授权。

## 名片分享与短链

- 使用方式：服务人员管理 → 对应人员「分享」→ 选择微信好友或群聊；也可以打开云端名片后从右上角菜单转发。商家预览中联系和预约仍不可用，但转发出去的是不带预览标志的客户页面。
- 好友实际打开需要小程序版本可访问、相应版本的后端可用，且云端存在该人员。开发/体验版本受微信成员权限限制，普通客户需使用已发布版本。开发者工具的本地 D1 资料不会随分享自动复制到线上；手机开发版预览使用线上 API，因此电脑本地创建的人员不能直接在手机打开，需要在线上重新创建。
- 原生转发不需要服务端调用微信生成链接，也不会为每次分享触发微信登录。人员被删除后，原来的分享卡片仍可能留在聊天中，但打开会显示不可查看。
- 微信 [URL Link](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/url-link.html) 是可在短信、网页等使用的 HTTPS 链接；[Short Link](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/shortlink.html) 是微信内使用的 `#小程序://…` 链接。按当前官方文档，这两项生成能力面向非个人主体开放，当前未接入。以后接入应在服务端持有 `access_token`、校验人员归属并生成公开详情路径，不能把 AppSecret 或服务端令牌放到客户端。

## API 环境

在 `miniprogram/config/api.ts` 中配置 API 根地址，客户端根据 `wx.getAccountInfoSync().miniProgram.envVersion` 和 `wx.getDeviceInfo().platform` 选择环境。只有开发版且运行于微信开发者工具时使用 localhost，其余情况使用线上地址：

| 环境及运行平台         | API 地址                 | 用途                          |
| ---------------------- | ------------------------ | ----------------------------- |
| `develop` + `devtools` | `http://localhost:8787`  | 电脑开发者工具，本地后端      |
| `develop` + 真机       | `https://api.ryandev.cn` | 手机预览 / 真机调试，线上后端 |
| `trial`                | `https://api.ryandev.cn` | 体验版，线上后端              |
| `release`              | `https://api.ryandev.cn` | 正式版，线上后端              |

客户端自动选择地址，无需在扫码预览或发布前手动切换。真机开发版、体验版和正式版目前共用线上后端及其数据，并非独立的预发布环境；真机预览中的创建、编辑和预约操作会写入线上数据库。

- 手机上的 localhost 指手机本身，不能访问电脑的后端，因此真机开发版按运行平台自动选择线上 API。线上后端与 D1 必须已部署并具备当前接口和表结构；本地数据重置不会影响线上账号、登录会话或店铺。不要通过网络失败自动切换 API，以免混用本地和线上数据。
- 在微信公众平台的服务器域名配置中，将 `https://api.ryandev.cn` 添加为 **request 合法域名**；域名须满足微信平台的备案、证书等要求。本地关闭域名校验不代表线上已配置完成。
- AppID 不是密钥，可以填写在项目配置中；AppSecret、数据库凭据和其他服务端密钥绝不能放进小程序代码。
- Token 按 API 地址隔离保存在本地，通过 `Authorization: Bearer ...` 发送；D1 仅保存 Token 哈希。登录响应不返回 OpenID 或账号手机号，公开页只展示商家主动填写的店铺联系电话。
- 上线前需在微信公众平台配置完整隐私保护指引：微信身份、店铺与人员公开资料、客户手动填写的联系人 / 电话 / 意向时间 / 备注、向对应商家提供信息的用途、保存期限、删除与申诉渠道；如开启服务器 IP 白名单也需配置。运营方仍需落实数据保留 / 删除机制，当前没有自助删除预约历史或自动到期清理功能。页面勾选与用途提示不能代替平台隐私合规配置；不要求开通微信手机号能力。
